# Test fixtures

Small, deterministic inputs for the test suite. Nothing here is used by production code paths.

## `vaastav/` — real-data excerpts
Subsets of the pinned historical repository
(`github.com/vaastav/Fantasy-Premier-League` @ `9779cdbc0c07f6c900c2d0c181ddf6bb9c800f88`),
mirroring its directory layout so the production pipeline reads them unchanged via
`LocalDirTransport`. Generated by `infra/scripts/make_test_fixtures.py`; **no values altered**:

| Season | Contents |
|--------|----------|
| 2024-25 | GW1–5 player rows (contract columns), GW1–5 fixtures, teams, players (contract columns) |
| 2025-26 | GW1–5 (includes the upstream exact-duplicate rows the quality gates must handle) |
| 2026-27 | GW1 rows, full published schedule, start-of-season bootstrap snapshot |

Licence/attribution: repository MIT; data © fantasy.premierleague.com / understat.com.

## `fpl_api/` — FPL-API-shaped contract fixtures
`bootstrap-static.json` and `fixtures.json` are the 2026-27 excerpt above **reshaped** into the
documented FPL API response shape by `infra/scripts/make_api_fixtures.py` (event deadlines derived
as first kickoff − 90 min). They exist because the live API is unreachable from the build
environment; they test parsing/canonicalisation, not live behaviour.

`manager/` (added in M3) contains **synthetic** manager payloads (entry, history, picks,
transfers) constructed by hand in the documented API shape. They are not any real manager's data.
